# med_automatization_BMM
Репозиторий для разработки сервиса автоматизации медицинских процессов в крупной многопрофильной медицинской сети

# локальный запуск
1. Поднять БД: `docker run --name clinic-db -e POSTGRES_USER=postgres -e POSTGRES_DB=clinic -e POSTGRES_PASSWORD=postgres -p 5435:5432 -d postgres:16`
2. Запустить db_init.py

# запуск через Docker
## тестирование
Проверяется корректность составленных запросов к БД, права доступа и многопоточность. Тесты вынесены в отдельный сервис tests под профилем test, поэтому при обычном  `docker compose up --build` они не запустятся.
Запуск на общей сети вместе с БД: `docker compose --profile test up --build tests`

# возможные проблемы

## models pulling 

1. Возможно при первом запуске контейнера произойдет ошибка и оллама не сможет скачать модель, для того чтоб она смогла это сделать, нужно отключить VPN.
2. Не стоит делать `docker compose down -v`, иначе придется снова ждать пока скачаются все модели, а это не быстро.

## rag

Сервис `rag-init` проверяет готова ли база знаний или нет если в ней, есть хотя бы одна запись, он запускается в фоновом режиме что бы не ждать пока все загрузится и перенесется в бд, так что если его прервать во время формирования записей, база знаний будет не полная, что бы он занова заполнил ее, нужно очистить табличку `clinic.medical_knowledge_base`.


## неудачная инициализация бд

Обязательно стоит смотреть лог консоли бд при первом запуске через ` docker compose logs -f db `, в зависимости от системы могут быть проблемы с файлом init_roles.sh, эту проблему можно решить изменив `Line Separator` этого файла.

## проблемы с ботом

Логи работы бота можно посмотреть в ` docker compose logs -f patient-ui `.
